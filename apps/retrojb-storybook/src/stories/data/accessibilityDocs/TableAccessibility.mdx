# Table Accessibility

Extracted from `packages/ui/src/components/data/Table/styles.ts`, plus the
wiring in `Table.tsx` and `parts.tsx` and the prop contract in `types.ts`.
Ratios are the measured output of
`npm run check:contrast --workspace=@retrojb/docs`, except the selected-row
tint, which is noted where it appears.

A data table has more ways to fail an audit than any other component here, and
most of them are structural rather than visual: a missing caption, a header that
labels the wrong columns, a scroll container no keyboard can reach, a sort
control that is a `<div>`. Those are decided by the component rather than left
to each call site.

## WCAG Standard and Expectations

| Criterion                         | Level | How the component meets it                                                                       |
| --------------------------------- | ----- | ------------------------------------------------------------------------------------------------ |
| 1.3.1 Info and Relationships      | A     | Native `<table>` semantics; `scope` on every `<th>`, tracking the cell's real span               |
| 1.4.1 Use of Color                | A     | Sort direction is a glyph as well as `aria-sort`; selection needs an in-row control              |
| 1.4.3 Contrast (Minimum)          | AA    | Cell text, header text and the empty-state message all clear 4.5:1 in both themes                |
| 1.4.11 Non-text Contrast          | AA    | The header/body boundary uses `--border-strong` at 4.26:1; vertical rules are decorative only    |
| 2.1.1 Keyboard                    | A     | The scroll container is focusable, so a horizontally scrolling table can be scrolled by keyboard |
| 2.3.3 Animation from Interactions | AAA   | `motion-reduce:transition-none` on the row and sort-button transitions                           |
| 2.4.6 Headings and Labels         | AA    | `caption` is a required prop, so the table always has a name                                     |
| 2.4.7 Focus Visible               | AA    | Same 2px `outline` as `Button`, `Link` and `Input`, on the sort buttons and the scroll region    |
| 2.4.13 Focus Appearance           | AAA   | 2px thickness plus a 2px offset                                                                  |
| 2.5.8 Target Size (Minimum)       | AA    | A sort button fills its entire header cell — 36/40/48px tall, all above the 24px floor           |
| 2.5.5 Target Size (Enhanced)      | AAA   | `lg` only, at 48px. `md` at 40px is 4px short of 44px                                            |
| 4.1.2 Name, Role, Value           | A     | Sorting is a real `<button>`; `aria-sort` carries the state                                      |

### The caption is required, by the type checker

`caption` is a required prop on `ITableProps`, the same decision `Input` makes
about `label`. A table without one leaves a screen reader user in a grid of
numbers with nothing saying what they are.

It is rendered as a real `<caption>`, as the first child of `<table>`, by the
component rather than by a `<Table.Caption>` part — a caption is only valid in
that one position, and a part could be put somewhere else or left out.

When the design has no room for visible caption text, use `captionHidden`:

```tsx
<Table table={table} caption="Open invoices" captionHidden />
```

That applies `sr-only`. The caption is visually gone but still in the
accessibility tree, still the table's name, and still what labels the scroll
region below. `hidden` or `display: none` would remove it from all three.

### The scroll container is a focusable region

A table wider than its column is the normal case, so the component always
renders an `overflow-x-auto` container around it — and a scrolling box that is
not focusable cannot be scrolled without a pointer, which fails 2.1.1.

```html
<div role="region" aria-labelledby="…-caption" tabindex="0">
  <table>
    <caption id="…-caption">
      Open invoices
    </caption>
  </table>
</div>
```

`tabindex="0"` makes it reachable. `role="region"` gives the resulting tab stop
a reason to exist when a screen reader lands on it, and a region needs an
accessible name to be announced as anything at all — which is what
`aria-labelledby` is doing. It points at the caption rather than duplicating the
text, so the region's name and the table's name cannot drift apart.

Because it is focusable, it carries the same focus indicator as every other
focusable surface in the package.

### Sorting is a button, and the state is `aria-sort`

Header cells become sort controls when the column can sort, which is a property
of the table instance rather than of this component. Registering
`rowSortingFeature` is what turns them on; leaving it out, or passing
`enableSorting: false`, renders plain header text with no button and no
`aria-sort`.

The control is a real `<button type="button">` inside the `<th>` — in the tab
order, operable with Enter and Space, announced as a button (2.1.1, 4.1.2). A
click handler on the `<th>` would be none of those things.

The button fills the whole cell. The size padding sits on the button rather than
on the `<th>` for exactly this reason, so the target is the full header cell
rather than a text-sized box inside it.

### Direction is announced and drawn

`aria-sort` on the `<th>` is what assistive technology reads:

| Column state       | `aria-sort`    | Glyph |
| ------------------ | -------------- | ----- |
| Sortable, unsorted | `"none"`       | `⇅`   |
| Sorted ascending   | `"ascending"`  | `▲`   |
| Sorted descending  | `"descending"` | `▼`   |
| Not sortable       | absent         | none  |

Sortable-but-unsorted columns carry `aria-sort="none"` rather than nothing, so a
screen reader user can tell a sortable column from a fixed one before activating
anything.

The glyph is `aria-hidden`, because `aria-sort` already says it. It exists so
that direction is not conveyed by colour or by position alone (1.4.1).

### `scope`, and columns of uneven depth

Every generated `<th>` gets a `scope`, chosen from how many columns the cell
actually covers: `colgroup` when it spans more than one, `col` otherwise. Keying
off the span rather than off whether the header has sub-headers matters in both
directions — a group column with one child spans one column and labels one
column, and a vertically merged header has a sub-header while still covering
one.

Nested columns of uneven depth are merged rather than padded. TanStack stacks
placeholder headers above a shallow column's real header so every header row
accounts for every visible column, reporting the chain's height as `rowSpan` on
the topmost one and `0` on the rest. The component skips the zeroes and spans
the survivor:

```html
<tr>
  <th scope="col" rowspan="2">Invoice</th>
  <th scope="col">Money</th>
</tr>
<tr>
  <th scope="col">Amount</th>
</tr>
```

The alternative — rendering placeholders as empty cells — puts a blank `<th>`
above a header that has text, and if that blank cell is also a sort control it
is a button with no accessible name at all (4.1.2).

### Selection is the checkbox, not the tint

`<Table.Row selected>` tints the row and sets `data-selected`. It announces
nothing, and cannot: ARIA supports `aria-selected` on rows inside a `grid`, not
on rows inside a `table`.

So a selectable table needs a checkbox or radio in one of its cells. That is
what conveys the state to assistive technology, and it is also what keeps the
state off colour alone (1.4.1):

```tsx
<Table.Row key={row.id} selected={row.getIsSelected()}>
  <Table.Cell>
    <input
      type="checkbox"
      checked={row.getIsSelected()}
      onChange={row.getToggleSelectedHandler()}
      aria-label={`Select invoice ${row.original.id}`}
    />
  </Table.Cell>
  …
</Table.Row>
```

### Target size

A sort button is as tall as its header cell: 36px at `sm`, 40px at `md`, 48px at
`lg`. All three clear the 24px minimum in 2.5.8. Only `lg` reaches the 44px
enhanced target in 2.5.5, the same caveat `Button` and `Input` carry — the
scales are aligned so the three line up in a toolbar.

## Colors

The table sits on `--surface-raised`, so its pairings are measured against that
rather than against `--background`.

### Text (needs 4.5:1)

| Role              | Pairing                                    |  Light |    Dark |
| ----------------- | ------------------------------------------ | -----: | ------: |
| Cell text         | `--foreground` on `--surface-raised`       | 17.8:1 |  14.3:1 |
| Header text       | `--foreground` on `--surface`              | 16.6:1 | 15.34:1 |
| Caption           | `--foreground-muted` on `--surface-raised` | 6.43:1 |  7.39:1 |
| Empty state       | `--foreground-muted` on `--surface-raised` | 6.43:1 |  7.39:1 |
| Sort button hover | `--accent-text` on `--surface`             | 5.58:1 |  8.14:1 |

Header cells are `bg-surface` unconditionally, not only when `stickyHeader` is
set. A sticky header scrolls body rows underneath itself and has to be opaque;
making that conditional means the day the variant is set some other way, rows
show through.

### Borders and focus ring (needs 3:1)

| Boundary                  | Pairing                                 |  Light |   Dark |
| ------------------------- | --------------------------------------- | -----: | -----: |
| Header / body rule        | `--border-strong` on `--surface-raised` | 4.26:1 | 3.59:1 |
| Row rules, vertical rules | `--border` on `--surface-raised`        |    n/a |    n/a |
| Container edge            | `--border` on `--background`            |    n/a |    n/a |
| Focus ring                | `--focus-ring` on `--surface-raised`    | 5.98:1 | 7.59:1 |

The focus ring on `--surface-raised` is a pairing the table introduced — it
carries one on the scroll container and one on every sort button, and neither
the page nor `--surface` is what sits behind them. It is checked by
`check:contrast` under `focus ring on raised`, alongside the pairings the table
shares with the other components.

The rule separating headers from data uses `--border-strong`, because it is the
boundary that distinguishes labels from values and so is doing more than
decoration. Row rules and the `bordered` variant's vertical rules use
`--border`, which is decorative: they group nothing that position does not
already group, and they are never the only thing identifying a cell, so 1.4.11
does not apply to them.

The colours are side-scoped in the stylesheet — `border-b-border-strong` rather
than `border-border-strong` — which is a correctness matter rather than a
stylistic one. tailwind-merge treats `border-<color>` as one group, so the
`bordered` variant's vertical-rule colour would otherwise replace the horizontal
one and silently downgrade the header boundary to decorative.

### The selected row tint

`bg-accent/10` composites to roughly `#e7effb` on light and `#242d38` on dark
over `--surface-raised`, leaving `--foreground` at about **15.4:1** and
**11.9:1**.

Those two are calculated rather than measured: `check:contrast` compares pairs
of named tokens, and a composited tint is not one.

Striping is dropped for a selected row, in the component rather than in CSS.
`odd:bg-surface` and `bg-accent/10` have the same specificity, so left to the
cascade which one painted a selected odd row would depend on the order the two
utilities happened to appear in the compiled stylesheet.

One thing to know before reading `dist/styles.css`: Tailwind emits
`background-color: var(--color-accent)` ahead of the `color-mix()` rule as an
`@supports` fallback, and a solid accent behind `--foreground` would be about
2:1. It never applies — `color-mix()` shipped in Chrome 111, Safari 16.2 and
Firefox 113, all at or below the Safari 16.4 / Chrome 111 / Firefox 128 floor
Tailwind v4 itself requires.

## Aria

Everything below is wired by the component. The caption id comes from `useId`,
which matters specifically because it produces ids that match between the server
and client render — hand-written ones stop doing that as soon as a second table
appears on a page.

| Attribute             | On               | Set when                     | Value                                           |
| --------------------- | ---------------- | ---------------------------- | ----------------------------------------------- |
| `role="region"`       | Scroll container | Always                       | `region`                                        |
| `tabindex`            | Scroll container | Always                       | `0`                                             |
| `aria-labelledby`     | Scroll container | Always                       | The generated `…-caption` id                    |
| `id`                  | `<caption>`      | Always                       | A generated `…-caption`                         |
| `scope`               | Every `<th>`     | Always                       | `colgroup` when spanning >1 column, else `col`  |
| `colspan` / `rowspan` | `<th>`           | The cell spans more than one | The header's own span                           |
| `aria-sort`           | `<th>`           | The column can sort          | `ascending`, `descending` or `none`             |
| `aria-hidden`         | The sort glyph   | Always                       | `true` — `aria-sort` already carries the state  |
| `data-selected`       | `<tr>`           | `selected` is `true`         | `"true"` — for styling and tests, not announced |

### The empty state spans the table

An empty row model renders one cell across every column rather than an empty
`<tbody>`, which reads as a broken table instead of an empty one. The span comes
from `getLeafHeaders().length`, which already reflects column visibility, so it
stays correct without the table having to register `columnVisibilityFeature`.

```tsx
<Table table={table} caption="Open invoices" />
// -> <td colspan="4">No results.</td>
```

Override the message with `emptyState` on `<Table.Body>`.

### Alignment belongs to the column

`align` is a per-cell prop, because a column of figures reads better end-aligned
while its neighbours stay at the start. A generated table has no call site to
put it on, so the component also reads `meta.align` off the column definition:

```ts
const features = tableFeatures({
  columnMeta: {} as { align?: "start" | "center" | "end" },
});

helper.accessor("amount", { header: "Amount", meta: { align: "end" } });
```

The `justify-*` half of the variant is what keeps a sortable numeric header's
button contents on the same edge as the numbers under it, since the button is a
flex container.

### Styling a table this component does not own

`tableStyle()` is a slot function and is callable from a server component. Use
it for a small static table with no TanStack instance behind it — but the
caption, the focusable region, the `scope` attributes and the `aria-sort` wiring
above are then yours to reproduce:

```tsx
const slots = tableStyle({ size: "sm" });

<div
  className={slots.root()}
  role="region"
  aria-labelledby="totals"
  tabIndex={0}
>
  <table className={slots.table()}>
    <caption className={slots.caption()} id="totals">
      Totals
    </caption>
    <thead>
      <tr className={slots.row()}>
        <th scope="col" className={slots.headerCell()}>
          <span className={slots.headerLabel()}>Region</span>
        </th>
      </tr>
    </thead>
  </table>
</div>;
```
