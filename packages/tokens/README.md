# @retrojb/tokens

Design tokens for `@retrojb/ui`, as CSS custom properties: three colour ramps,
semantic colours, spacing, radii, border weights and type. Light and dark themes
ship in one stylesheet.

## Using it

If you use `@retrojb/ui`, you already have these: `@retrojb/ui/styles.css`
bundles them. Import this package directly when you want the tokens without the
components, or in an app with its own Tailwind build:

```css
@import "@retrojb/tokens";
```

| Import                      | What you get                                         |
| --------------------------- | ---------------------------------------------------- |
| `@retrojb/tokens`           | Both themes. Follows the OS, `data-theme` forces one |
| `@retrojb/tokens/light.css` | Light only                                           |
| `@retrojb/tokens/dark.css`  | Dark only                                            |

Pick one of the three. Each is complete on its own.

## Themes

`@retrojb/tokens` follows `prefers-color-scheme`. Set `data-theme` on `<html>`
to force a theme:

```html
<html data-theme="dark"></html>
```

Each themed colour is a single `light-dark()` declaration, and the
`color-scheme` property picks the branch. `light-dark()` is Baseline since May
2024 (Chrome 123, Firefox 120, Safari 17.5). Tailwind's and Next.js's CSS
pipelines can transpile it for older targets.

## Overriding

Every token is declared inside `@layer theme`, so an unlayered rule in your app
wins without `!important`:

```css
:root {
  --accent: #6d28d9;
}
```

Override a ramp step (`--primary-8`) to retint everything built on it in both
themes, or a semantic token (`--accent`) to change one role.

## Editing the tokens

The sources are in `src/`. `dist/` is generated by `npm run build`.

| File            | Holds                                                   |
| --------------- | ------------------------------------------------------- |
| `src/base.css`  | Theme-independent tokens: spacing, radii, borders, type |
| `src/light.css` | Every colour token, with its light value                |
| `src/dark.css`  | Only the colour values that differ in dark mode         |

`dark.css` is an overlay. The build fails if it declares a token `light.css`
does not, or one whose values are not literal colours, because `light-dark()`
accepts nothing else.

After changing a colour, run the contrast check. It reads `src/light.css` and
`src/dark.css` directly:

```sh
npm run check:contrast --workspace=@retrojb/docs
```
